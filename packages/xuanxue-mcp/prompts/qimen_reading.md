# 奇门遁甲解读流程

本流程配合 `qimen` 工具使用。在 MCP 客户端中调用 `qimen` 工具；在 Agent Skill 环境中运行 SKILL.md 给出的 CLI 命令（`node scripts/qimen_cli.cjs`），参数与输出字段相同。两种方式都禁止心算替代。奇门问的是"此刻这件事"，不需要出生信息；不要把一局扩大成终生命运，长期命局更适合八字。

## 第 1 步：访谈

核心信息缺失时不起局。先确认：

1. 所问之事，一句话说清具体事情。问题过宽或涉及多件独立的事时，先拆开追问。
2. 起局时间：默认取"问事当下"，不传 `cast_time`，由引擎取当前时刻，你不得臆测时辰。只有用户明确要为某个指定时刻复盘时，才传该时刻（ISO 格式，带时区偏移）。
3. 事件发生时间（面试、开庭、签约的时刻）属于事项背景，不是起局时间，除非用户明确要求按那个时刻起盘。
4. 所在时区：默认北京时间（`Asia/Shanghai`）；海外必须确认时区并传 `timezone`。
5. 最想判断的结果（能不能成、何时动、如何选、往哪走、避开什么）、现实进展、主动方与被动方。
6. 生辰仅作背景，愿意提供时才传 `birth`（`date`、`time`、`gender` 必填）；它不参与用神与评分，不得据此改写盘面判断。

医疗、法律、投资、孕产、失踪等高风险主题，必须提示现实中的专业路径。

## 第 2 步：调用 `qimen` 工具

- 只要盘面：`mode: "chart"`。
- 判断具体事情：`mode: "question"`，把问题写进 `question`。
- 不支持多时辰择时：不能一次扫描并比较多个候选时刻。用户要"选日子、选时辰"时如实说明，只能对用户指定的单一时刻分别起局、逐局解读，不替用户跨局排序。应期以 `judgments.timing` 为准。

## 第 3 步：解读

盘面事实一律取自 `chart`：

- `chart.palaces`：九宫，数组顺序即洛书行优先顺序。每宫有 `name`、`door`、`star`、`god`、`sky`、`earth`、`stem_relation`、`prosperity`、`isKong`、`hasMa` 等字段。门、星为繁体字，引用时照原样或转简体，不得换成别的符号。
- `chart.zhiFuStar`、`chart.zhiShiDoor`、`chart.xunHead`、`chart.juResult`、`chart.qimenData` 用于局名、值符值使、空亡、马星。
- 用神由 `judgments.yongshen` 的符号对应到 `chart.palaces` 定位：日干宫看 `isDayStem`，时干宫看 `isHourStem`，值符宫 `isZhiFu`，值使宫 `isZhiShi`，门星神按 `door`、`star`、`god` 字段找。

报告必须覆盖的语义，章节自行安排，简单问题可以短答：

1. 直接回应用户最关心的问题。
2. 观察对象与取用逻辑：`judgments.yongshen` 取了哪些用神、为何。
3. 主要支撑与主要制约、风险；支撑与风险并列，风险之后给应对建议。
4. 核心用神宫的第二层解读（`palace_depth_reading`）：不止报符号，要读到天盘干与地盘干的生克方向（`stem_relation`）、旺衰（`prosperity`）、门星神组合的合力或矛盾。干生克或旺衰与门星神表层吉凶相反时，必须点出这层张力，不得只取有利面。
5. 有名格（`formations_rendered`）：`judgments.formations` 命中的吉格凶格逐条列出，每条说明格名、落在哪一宫、影响哪个用神、与核心用神的关系、现实含义与倾向。没有命中时明确说"本局无有名格命中"。不得只写"格名加通用象义"。
6. 主体与目标的关系：日干与用神的生克、同宫、比和。
7. 应期：只能使用 `judgments.timing` 给出的候选（`p1_candidates`、`p2_scan.candidates`），并结合现实常理过滤不合理时段；应期是可能启动、沟通、兑现或适合复核的窗口，不保证事件必然发生。没有候选时不自行编造日期。
8. 可执行建议：必须绑定具体的盘面信号（某宫、某门星神、某格局、某应期）。
9. 限制：低置信、开放取用与现实边界，按通用守则转告 `limitations`、`confidence`、`warnings`。

极性修正：`judgments.polarity` 里同一信号在不同问题域含义不同；引用时同时保留有利面与残余风险，不把"带风险的正面"洗成纯吉。

评分只转译成趋势措辞：不展示 `score` 里的 `deltas`、数值调整与置信度数字，`score.level` 只说成趋势。

## 同局追问

追问前先判断是哪一类：同一件事深挖，新增现实信息改变前提，还是另一件事（需要另起一局）。

- 深挖与修订：不重新起局、不修改原结论的评分、不静默覆盖原结论，只增补内容；修订写成"原结论，因新情况调整为……"，只引用已有的工具结果，可对指定宫位或方位重读。
- 另一件事：重新调用 `qimen` 起新局。

## 口径

`conventions.qimen_method` 给出本次起局方法（时家转盘、拆补法、天禽寄坤），`conventions.timezone` 给出时区。起局时刻以 `input.cast_time` 为准，向用户说明实际起局时间。
