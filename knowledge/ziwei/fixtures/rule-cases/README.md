# 紫微知识回归命例

本目录及相邻的 `report-cases/`、`regression-cases/` 只保存可重复执行的结构化测试资料。不得复制真实用户档案到 fixture。

## 数据政策

- `synthetic`：由测试人员构造的出生日期、时刻与档案 ID，不对应已知个人；这是默认方式。
- `public`：仅在确有必要时使用公开人物，并登记公开来源、用途和最小必要字段。
- 禁止保存姓名、邮箱、电话、详细地址、用户 profile ID 或可反查用户身份的组合字段。
- 修改命例必须经代码审查；仅修改预期值以绕过回归失败不视为有效修复。

首个基线 `regression-cases/baseline-v1.json` 使用三个纯虚构档案。时间校正值固定为零，目的是稳定覆盖排盘与报告链路，不表达任何现实人物判断。

## 指标定义

| 指标 | 定义 | v1 门槛 |
| --- | --- | --- |
| P0 规则命中率 | 得到预期规则 ID 且派生值完全一致的案例数 / P0 案例总数 | 100% |
| P0 冲突率 | 执行中触发 `RULE_FACT_CONFLICT` 的案例数 / P0 案例总数 | 0% |
| P1 解释命中率 | 实际命题集合与期望集合完全一致，且排除项均未出现的案例数 / P1 案例总数 | 100% |
| 无证据结论数 | 缺少 `matched_facts` 或 `evidence_ids` 的报告结论数 | 0 |
| 无效报告数 | 证据校验失败或结论数量偏离已登记基线的主题报告数 | 0 |

首个基线包含：

- 12 条已编译 P0 规则、14 个 P0 案例；
- 23 条 `reviewed` P1 解释命题、5 个精确召回案例；
- 3 个虚构档案、15 份主题报告、126 条有证据结论；
- 流年主题当前为零结论，因为尚无 `reviewed` 年度解释命题。

## 执行

```bash
npm run test:ziwei-knowledge
node scripts/eval-ziwei-knowledge.cjs --assert-baseline
```

评估输出不包含当前时间，因此同一知识版本应生成完全一致的 JSON。新增规则或解释命题导致基线变化时，应先核对来源和报告影响，再显式更新 `baseline-v1.json` 或建立新版本，不能静默接受漂移。
